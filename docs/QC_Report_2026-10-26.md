## 3. What was wrong, and what was done

### 3a. A bounce that arrives minutes after a send is missed by the FIRST sync (fixed in code, commits `9ad4175`, `6feefbe`)
Oxford Semantic Technologies: outreach bounced instantly, you synced, the card stayed in Contacted. The sync loaded its thread map from BigQuery *before* reading the mailbox and read the mailbox newest-first, so the bounce (linkable only through our own Message-ID) was read before the send it answered, matched nothing and was dropped on that first sync. The second sync, with the send now in the thread map, filed it and pulled the company back at 20:44; you then re-sent from your own inbox and set Contacted by hand at 20:47. Three fixes: the scan walks oldest-first and remembers every Message-ID it files within the run (so the first sync catches it); a fifth matching rung links a headerless NDR by the dead address it quotes; and the delivery check now honours `stage_set_by = human`, so a row you placed is never demoted again by a stale bounce (your manual send went from your inbox, which the sync never reads, so without this the next sync would have undone your move).

### 3b. 112 companies held template addresses from before the 16 Sep guard (fixed in data)
`your@email.com`, `john@company.com`, `you@example.com`, Sentry and Wix tracking hashes. The guard that refuses these has been live since 16 Sep, but the retro audit for rows enriched earlier had only ever been dry-run. It is now applied: 99 cleared with a note on the card, 12 obfuscated addresses decoded to the real one. None of the 112 had been emailed at the bad address; EquiTech (the "Hi Your" modal) you had already corrected by hand.

### 3c. Band chip was on the old mandate (fixed in code, commit `3ee4df0`)
Target Band read £2.5M–40M, so an £11.8M company showed "Target Band" while scoring zero on size. Now £1M–8M as you asked, defined once with a SQL twin and the frontend mirror pinned by a test. The next rescore relabels every stored chip. The fit score's own revenue-size scale (2–6M full marks) is unchanged on purpose: the chip is the envelope, the score is the sweet spot. Say the word if you want the score to follow 1–8M too.

### 3d. Two stale tests (fixed, commit `b06a939`)
`tests_reply_rule` and `tests_thread_match` had been failing since the predicate was parameterised and the sync body moved; both were assertion drift, not product faults. The suite is 35/35.

### 3e. One row needs a human decision: Facewatch
Sits at Responded, moved there by you, with no genuine reply in the email log. The reply rule correctly refuses to touch a human-placed row; the Check Stages button on the Pipeline will ask. "Keep it" stamps `reply_exempt` and silences the alarm for good; "Move back" puts it in Contacted. This is the only non-zero alarm in the system.

## 4. Built but not running (the limiting factors)

These are the things most likely to be costing you deal flow or investor reach right now. None is a bug; each is waiting on one input.

**4.1 Nightly SmartFill is paused (since 9 Oct).** `AUTO_SMARTFILL_ENABLED=0` and the scheduler job is paused, set when the Gemini wallet was the concern. Gemini has been on post-paid Vertex since 20 Oct, so the reason for the pause is gone. 3,613 companies sit at Qualified today and the never-enriched queue only moves when someone presses a button. Resume: `gcloud scheduler jobs resume averroes-auto-smartfill` plus `--update-env-vars AUTO_SMARTFILL_ENABLED=1`. Set a GCP budget alert on the Vertex AI SKU first (not yet done).

**4.2 Hunter verification quota is exhausted.** Contact sources on rows enriched since at least 10 Sep read "founder guess not used: … verifier error: You've reached the limit for the number of verifications per billing period". The waterfall then falls back to a colleague's address or a shared inbox, and the founder's likely address is thrown away unverified. This is quietly lowering the quality of who we write to. Either top up the Hunter plan or set `EMAIL_VERIFIER_API_KEY` to another verifier; no code change needed.

**4.3 The investor loop has never been switched on.** 14,035 investors Identified, 6 Researched, 0 Contacted, 1 Responded. The machinery (gate, triage, InvestorFill, priority ranking, v3 email, OOO, bounce, follow-up) is built and tested, but three inputs are missing: Ellie's mailbox on Cloud Run (TBU #166; the Gulf desk currently falls back visibly to Bea's address), the UK/EU email copy (TBU #174) and the mandate-only copy (TBU #175). Only the GCC email exists, so the 1,916 UK/EU and 463 mandate-only qualifiers cannot be written to at all. The 10,907 unknown-location investors go through InvestorFill to find their country, and bulk InvestorFill has only ever done 6.

**4.4 The 7 AM Granola job is not created.** The sync works from the button and the token URL; the scheduler script (`backend/scripts/setup_calls_sync_schedule.sh`) has been written but not run, so call notes only land when someone clicks.
